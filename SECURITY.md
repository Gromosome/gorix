# Security Policy

## Reporting a Vulnerability

Please do not open a public GitHub issue for suspected security vulnerabilities.

Email security reports to:

**pressnavek@gromosome.com**

Include as much detail as possible:

- Affected package, module, version, commit, or branch.
- Clear reproduction steps or proof of concept.
- Expected and actual impact.
- Any affected configuration, database driver, or runtime environment.
- Whether the vulnerability is already public or being actively exploited.

## Response Process

The maintainers will review the report, ask for clarification if needed, and coordinate a fix before public disclosure when appropriate.

Security fixes may be released as patches across one or more workspace modules depending on the affected code.

## Supported Versions

Until the project publishes a formal version support matrix, security fixes target the current default branch and the latest released module versions where practical.

## Responsible Disclosure

Please give maintainers reasonable time to investigate and release a fix before publicly sharing vulnerability details. Do not access, modify, or exfiltrate data that does not belong to you while researching a vulnerability.
